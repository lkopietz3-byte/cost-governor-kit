# Threshold: rendered improvement loop

This applies Claude's local `prompt-forge/CRITIC-RUBRIC.md`, `BEYOND-REAL.md` and P9 to the actual Cost Governor example. It is a local design workflow, not a new agent runtime or live integration.

## Current intent

- **Insight:** a request gets work only after its price estimate and capacity reservation pass; uncertainty retains a hold.
- **Audience:** PlanrLabs portfolio viewers and builders inspecting an SDK decision.
- **Feel:** a restrained instrument panel, museum specimen lighting, a single moving signal.
- **Assets:** the original dark tokens, serif phrase, SVG map, immutable SDK journals and v1 notebook.
- **Tier:** light discipline in CSS/SVG. The upper-left key, lower-right contact shadows and material edges use the existing palette. State glow follows the recorded event; the idle Request outline invites inspection.
- **Preserve:** actual SDK execution, prefix-only visible counts, refusal bypassing Work, unknown usage, native keyboard access and saved-data recovery.

## Roles and stop condition

The director fixes one insight and the permitted scope. One builder edits source. A deterministic measurer captures the real page and checks geometry, source hashes, controlled steps and errors. A different critic sees pixels and measurements, scores ten dimensions with concrete evidence, and never edits. Native tests verify the behavior that attractive pixels cannot prove.

A round fixes at most three items; there are at most three rounds. One viewport is held out from the builder. The critic's bar is no score below 3, hierarchy/responsiveness/informativeness/truthfulness at least 4, total at least 38/50. That is advisory visual judgment, not user acceptance or product outcome evidence.

Round 1 applies the three baseline fixes: one-screen workspace, 44px controls and coherent light. The clock hook is supporting measurement infrastructure. Conditions on a phone and the complete result open in labeled native dialogs. Long evidence and saved lists can scroll within their named panels. Short/zoomed windows retain document reflow.

## Reproduce without new dependencies

Use the prepared local SDK, existing Playwright and local Chrome. The browser harness checks actual exported journals, captured-prefix arithmetic, moving/paused SVG positions, ambiguous and duplicate requests, notebooks, keyboard flow, source failure and loopback restrictions. The rendered measurer additionally checks the four reference sizes and a held-out size, including required content, hit areas, dialogs and immutable hook state.

For each run, bind rendered HTML/CSS/modules and the measurement script to hashes. Reopen the owning source before promotion and refuse overlapping changes. Preserve prior receipts as evidence for their own source, rather than replacing the baseline.

Contrast estimates do not establish complete accessibility: gradients, opacity, layering, font rendering and actual assistive technology need additional evaluation. Phone widths are browser emulation. Frame movement does not prove 60fps or execution latency.

## Research boundary

[Vision-Guided Iterative Refinement for Frontend Code Generation](https://arxiv.org/html/2604.05839) reports improvements using rendered visual critiques over three cycles on its evaluation tasks. That supports trying a bounded separate-critic loop; it does not establish the quality or ROI of this implementation. Claude's 38/50 baseline remains a historical judgment; fresh geometry reproduces its scroll and target failures.

Higher rendering tiers remain options: Blender Cycles for a specific hero, progressive browser path tracing for an appropriate paused product asset, or captured splats for an actual environment. This UI's information flow can be improved without adding those dependencies. Connect a real adapter event stream before describing this as live Jev/MCP activity.
